# PDF解析质量闸门

Phase 2A-0 对带文本层的 V2.3、V2.3.1和V2.4 PDF 使用本地、确定性的三层提取：普通文本用于章节和日期，页面布局文本用于证据定位，字符坐标用于重建详细观点表和历史路径矩阵。不得调用外部 LLM、在线 AI 或 OCR。

每条详细观点保留提取方法、PDF页码、文本范围、原文摘要、置信度、校验标记和质量状态。系统检查板块边界、五项字段完整性、状态唯一性、跨行串入其他板块名称，以及历史矩阵的66行与日期列结构。

- `verified_structure`：结构和来源证据一致，可进入发布确认；
- `needs_attention`：存在非阻塞疑点，管理端默认只显示异常；管理员阅读提醒并明确确认后可发布；
- `blocking_parse_error`：表格或历史矩阵无法可靠恢复，禁止进入 Ready 或发布。

历史矩阵恢复60至65行属于普通 warning，不把整份报告误判为失败；少量未映射词、跨页、合并B1标题、规范版本未逐字出现或个别解释字段偏短同样只是提醒。无法可信确定报告日期、PDF主体结构无法恢复、历史矩阵少于60行、明确状态冲突、严重字段串行、大量未映射词或冻结区被改写才是 blocking。warning/needs_attention 绝不自动发布，必须由管理员勾选确认，可留下审计说明。

行情缺失继续是非阻塞项。管理员手工修正只更新对应板块及审计版本，不得伪造原始提取证据。真实 PDF 回归样本只存在于本机忽略的 `var/` 目录；CI 使用脱敏小型 fixture。

本地真实样本可显式执行：`PYTHONPATH=backend python3.12 scripts/validate_real_pdf_fidelity.py --pdf <本机PDF路径>`。校验只读取文件并输出统计，不复制或提交真实PDF。
